# Liga1 Firebase Full Setup

This version keeps the existing Liga1 UI but changes authentication, account creation, wallet deposits, withdrawals, payment settings, and admin actions to Firebase-backed systems.

## Architecture

- **Frontend:** `index.html`
- **Admin:** `admin.html`
- **Authentication:** Firebase Authentication, Google only
- **Database:** Cloud Firestore
- **Server:** Firebase Cloud Functions, Node.js 20
- **Hosting:** GitHub Pages or Firebase Hosting
- **Wallet:** server-authoritative Firestore transactions

## Important

There are no test wallet rules in this package. Client users cannot write `users`, `transactions`, `depositRequests`, or `withdrawalRequests` directly.

Balance changes happen only inside trusted Cloud Functions.

Do not put Firebase Admin SDK service-account JSON files, private keys, payment gateway secrets, or other server secrets in GitHub.

## 1. Create Firebase project

Firebase Console:

1. Create/select your project.
2. Build -> Authentication -> Sign-in method -> enable **Google**.
3. Authentication -> Settings -> Authorized domains.
4. Add your GitHub Pages host, for example `yourname.github.io`.
5. Build -> Firestore Database -> Create database.
6. Project settings -> General -> Your apps -> Add Web app.
7. Copy the Web App config into `index.html` and `admin.html`.

If testing from localhost, add `localhost` to Authorized domains.

## 2. Install Firebase CLI

```bash
npm install -g firebase-tools
firebase login
```

Inside this folder:

```bash
firebase use --add
```

Select your Firebase project.

## 3. Install Cloud Functions dependencies

```bash
cd functions
npm install
cd ..
```

## 4. Deploy Firestore rules and functions

```bash
firebase deploy --only firestore:rules,functions
```

## 5. Create the first administrator

First sign in once through `index.html` using the Google account that should become the owner/admin.

Open the browser developer console and find the Firebase Auth UID, or inspect Firebase Console -> Authentication -> Users.

Then from the `functions` directory:

```bash
node set-admin.js YOUR_FIREBASE_AUTH_UID
```

Sign out and sign in again so the new custom claim is loaded into the ID token.

Open:

```text
https://YOUR_GITHUB_USERNAME.github.io/YOUR_REPOSITORY/admin.html
```

Only an account with the `admin=true` custom claim can use the admin panel.

## 6. Configure the payment QR

In `admin.html`:

1. Sign in as admin.
2. Put the official QR image HTTPS URL in **QR Image URL**.
3. Enter the available payment methods.
4. Enter payment instructions.
5. Save.

The player wallet page reads `settings/payment` and displays the configured QR.

## 7. Real deposit flow

1. Player signs in with Google.
2. Player profile is created server-side.
3. Player enters Free Fire nickname and UID.
4. Player opens Wallet.
5. Player pays using the official QR.
6. Payment remark must contain the player's Liga1 email.
7. Player submits amount, payment method and real transaction/reference ID.
8. Cloud Function creates a `pending` deposit request.
9. Admin checks the real payment in the payment provider/bank.
10. Admin approves only after verification.
11. Cloud Function transactionally adds coins and writes the ledger transaction.
12. If admin denies it, no coins are added.

## 8. Real withdrawal flow

1. Player requests withdrawal with amount, wallet and account ID.
2. Cloud Function transactionally checks available earnings.
3. Earnings are immediately reserved by moving the amount into `pendingWithdrawal`.
4. Admin sees the pending request.
5. Admin manually sends the real payment.
6. Admin clicks **Paid**.
7. Cloud Function marks the request paid and releases the pending amount.
8. If admin denies it instead, the same transaction returns the reserved amount to earnings.

This prevents double-spending caused by two browser tabs or repeated clicks.

## 9. Firestore collections

### `users/{uid}`

Server-owned account profile and wallet state.

Important fields:

- `uid`
- `email`
- `displayName`
- `photoURL`
- `freeFireUID`
- `freeFireNickname`
- `balance`
- `earnings`
- `pendingWithdrawal`
- `accountStatus`
- `isBanned`
- timestamps

### `depositRequests/{requestId}`

Pending/approved/denied real-money deposit verification records.

### `withdrawalRequests/{requestId}`

Pending/paid/denied withdrawal records.

### `transactions/{transactionId}`

Immutable wallet ledger generated by trusted server functions.

### `settings/payment`

Admin-managed payment QR URL and payment instructions.

## 10. Security model

Firestore rules intentionally deny direct client writes to wallet/account collections.

The client can only read its own profile, requests and transactions. Admins can read operational records using the Firebase Auth custom claim.

The functions validate authentication and admin authorization before performing privileged operations.

## 11. GitHub Pages

Commit the frontend files to GitHub and enable GitHub Pages.

Use the GitHub Pages host in Firebase Authentication -> Authorized domains.

Example:

```text
https://yourname.github.io/Liga1/
```

Authorized domain:

```text
yourname.github.io
```

The repository path is not added to Firebase Authorized Domains.
